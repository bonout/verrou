Terminale e agenti IA

I tuoi agenti usano i tuoi segreti. Senza mai vederli.

Verrou passa chiavi API e password ai comandi che un agente IA esegue, le tiene fuori dal suo contesto e dalla cronologia del terminale, e prima chiede a te: Touch ID sul Mac, Face ID sul tuo iPhone quando non ci sei.

Il problema dei segreti con gli agenti IA

Un agente di programmazione come Claude Code o Codex esegue comandi nel tuo terminale. Se un token si trova in un file .env, in una variabile d'ambiente o nell'output di un comando, finisce nel contesto dell'agente, nei log e a volte in una trascrizione inviata altrove. Incollare i segreti a mano non è sostenibile, e dare all'agente l'intero password manager è anche peggio.

verrou run: i segreti entrano, non escono

verrou run avvia un comando con i segreti che gli servono nel suo ambiente. I tuoi file contengono solo riferimenti, quindi puoi farne il commit:

# .env: nessun segreto qui dentro
GITHUB_TOKEN=verrou://GitHub/token
DATABASE_URL=verrou://Production%20DB/url

$ verrou --reason "deploy" run --env-file .env -- ./deploy.sh
Deploying with token <concealed by Verrou>
  • Output mascherato. Se il comando stampa un segreto, Verrou lo sostituisce con <concealed by Verrou> prima che arrivi al terminale o all'agente.
  • Approvati uno per uno. Ogni segreto chiede Touch ID, con il motivo indicato dall'agente (--reason o VERROU_REASON). Un'approvazione vale 5 minuti per quell'elemento e quel terminale.
  • Ricerca senza segreti. verrou search mostra titoli, nomi utente e siti, mai le password, così un agente trova da solo il riferimento giusto.

Lontano dal Mac? Approva dall'iPhone.

Quando lo schermo del Mac è bloccato o sei inattivo da un po', la richiesta arriva a Verrou sull'iPhone abbinato: "Il Terminale vuole leggere GitHub, motivo: deploy". Face ID, un tocco, e il comando prosegue. Se la cassaforte del Mac era bloccata, una sola approvazione la sblocca per quell'unico elemento.

  • End-to-end. Richieste e risposte passano dal tuo database privato iCloud, cifrate tra il Mac e le chiavi del Secure Enclave dell'iPhone. Nessun nostro server.
  • La chiave della cassaforte resta sul Mac. L'iPhone si limita ad approvare; non riceve mai la chiave della cassaforte del Mac.
  • La notifica non rivela nulla. Ti dice solo che c'è una richiesta in attesa; il motivo compare nell'app, dopo Face ID.

Server MCP e hook per il vostro agente

verrou mcp è un server MCP che Claude Code, Codex e Cursor possono usare (claude mcp add verrou -- verrou mcp). L'agente trova gli elementi e ottiene riferimenti, mai valori; per usarne uno lo chiede a Verrou e voi approvate.

  • Nomi, mai valori. L'agente vede i titoli, i nomi dei campi e i riferimenti verrou://. Esegue comandi con i segreti inseriti e riceve il loro output mascherato.
  • Ogni chiamata approvata a parte. Verrou mostra la riga di comando e i campi che riceve, e separatamente ciò che l’agente dice di voler fare. Approvate solo comandi che capite: la maschera nasconde solo i valori esatti, quindi un comando scelto dall’agente può comunque consegnargli un valore.
  • Una protezione in più. verrou hook install impedisce all'agente di leggere da solo i file .env e le chiavi private, e lo indirizza a verrou run.

Agente SSH e firma git

eval "$(verrou ssh-agent)" serve le chiavi SSH salvate nella tua cassaforte: ssh, git push e git commit -S funzionano, e ogni firma chiede la tua approvazione.

Il confronto

1Password offre un comando op run simile nella sua CLI, legato al suo cloud. Verrou fa lo stesso per una cassaforte sul tuo server Vaultwarden, con le approvazioni dal tuo iPhone; vedi Verrou o 1Password.
