Terminal und KI-Agenten

Deine Agenten nutzen deine Secrets. Sehen werden sie sie nie.

Verrou übergibt API-Schlüssel und Passwörter an die Befehle, die ein KI-Agent ausführt, hält sie aus seinem Kontext und deinem Terminalverlauf heraus und fragt dich vorher: Touch ID auf dem Mac, Face ID auf dem iPhone, wenn du weg bist.

Das Problem mit Secrets und KI-Agenten

Ein KI-Coding-Agent wie Claude Code oder Codex führt Befehle in deinem Terminal aus. Steht ein Token in einer .env-Datei, in einer Umgebungsvariable oder in der Ausgabe eines Befehls, landet es im Kontext des Agenten, in Logs und manchmal in einem Transkript, das anderswohin geschickt wird. Secrets von Hand einzufügen skaliert nicht, und dem Agenten deinen ganzen Passwort-Manager zu geben, ist noch schlimmer.

verrou run: Secrets rein, nie wieder raus

verrou run startet einen Befehl mit den Secrets, die er braucht, in seiner Umgebung. Deine Dateien enthalten nur Referenzen und können deshalb committet werden:

# .env: kein Secret darin
GITHUB_TOKEN=verrou://GitHub/token
DATABASE_URL=verrou://Production%20DB/url

$ verrou --reason "deploy" run --env-file .env -- ./deploy.sh
Deploying with token <concealed by Verrou>
  • Maskierte Ausgabe. Gibt der Befehl ein Secret aus, ersetzt Verrou es durch <concealed by Verrou>, bevor es das Terminal oder den Agenten erreicht.
  • Einzeln genehmigt. Jedes Secret fragt nach Touch ID, mit dem Grund, den der Agent angegeben hat (--reason oder VERROU_REASON). Eine Genehmigung gilt 5 Minuten für diesen Eintrag und dieses Terminal.
  • Suchen ohne Secrets. verrou search zeigt Titel, Benutzernamen und Websites, nie Passwörter, sodass ein Agent die richtige Referenz selbst findet.

Nicht am Mac? Genehmige vom iPhone aus.

Ist der Bildschirm deines Mac gesperrt oder warst du eine Weile inaktiv, geht die Anfrage an Verrou auf deinem gekoppelten iPhone: „Terminal möchte GitHub lesen, Grund: deploy“. Face ID, ein Tippen, und der Befehl läuft weiter. War der Tresor auf dem Mac gesperrt, entsperrt eine einzige Genehmigung ihn für genau diesen Eintrag.

  • Ende zu Ende. Anfragen und Antworten laufen über deine eigene private iCloud-Datenbank, versiegelt zwischen den Secure-Enclave-Schlüsseln von Mac und iPhone. Kein Server von uns.
  • Der Tresorschlüssel bleibt auf dem Mac. Das iPhone genehmigt nur; den Tresorschlüssel deines Mac erhält es nie.
  • Die Mitteilung verrät nichts. Sie sagt dir nur, dass eine Anfrage wartet; den Grund siehst du in der App, nach Face ID.

MCP-Server und Hooks für Ihren Agenten

verrou mcp ist ein MCP-Server, den Claude Code, Codex und Cursor nutzen können (claude mcp add verrou -- verrou mcp). Der Agent findet Einträge und erhält Referenzen, nie Werte; um eine zu verwenden, fragt er Verrou, und Sie bestätigen.

  • Namen, nie Werte. Der Agent sieht Titel, Feldnamen und verrou://-Referenzen. Er startet Befehle mit eingesetzten Geheimnissen und erhält deren Ausgabe maskiert.
  • Jeder Aufruf einzeln bestätigt. Verrou zeigt die Befehlszeile und die Felder, die sie erhält, und getrennt davon, wofür der Agent sie angeblich braucht. Genehmigen Sie nur Befehle, die Sie verstehen: Die Maskierung verbirgt nur exakte Werte, ein vom Agenten gewählter Befehl kann ihm also trotzdem einen Wert liefern.
  • Eine Leitplanke. verrou hook install hindert den Agenten daran, von sich aus .env-Dateien und private Schlüssel zu lesen, und verweist ihn auf verrou run.

SSH-Agent und Git-Signaturen

eval "$(verrou ssh-agent)" stellt die SSH-Schlüssel aus deinem Tresor bereit: ssh, git push und git commit -S funktionieren, und jede Signatur fragt nach deiner Zustimmung.

Der Vergleich

1Password bietet mit op run etwas Ähnliches in seiner CLI, gebunden an seine Cloud. Verrou macht das für einen Tresor auf deinem eigenen Vaultwarden-Server, mit Genehmigungen vom iPhone; siehe Verrou im Vergleich mit 1Password.
